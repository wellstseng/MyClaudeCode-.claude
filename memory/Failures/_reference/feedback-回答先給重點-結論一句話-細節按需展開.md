## 知識

- [觀] Wells 明令（2026-08-17）：**回答簡單明瞭、講重點**。實況：sys conf 案我用大表格＋逐檔清單＋反向驗證細節交付，他回「講太多 重點是什麼」；改成三句（問題／已修／等你）才對味。
- [觀] 標準形：**結論先行一句話 → 最多 3 條重點（問題根因／做了什麼／等使用者做什麼）→ 細節等他問**。表格、逐檔清單、驗證流水帳預設不出現在第一次回應。
- [觀] 與 IDENTITY「收尾報告四要素（做了什麼／屬總目標哪部分／成效／怎麼推進）」不衝突：四要素講**內容涵蓋面**，本條講**篇幅與層次**——四要素各一句即可，不是各一段。
- [觀] 省篇幅靠**砍不影響下一步的細節**（過程、被否決的選項、逐檔 diff 描述），不是把句子壓成密語；可讀性 > 壓縮。

## 行動

- 每則回應先寫結論句，再問自己「刪掉這段他的下一步會變嗎」——不會就刪
- 驗證細節／檔案清單留著備問，不主動鋪陳；使用者要細節會自己要
- 被說「太長／講重點」→ 立即重寫成 3 句以內，不辯解
