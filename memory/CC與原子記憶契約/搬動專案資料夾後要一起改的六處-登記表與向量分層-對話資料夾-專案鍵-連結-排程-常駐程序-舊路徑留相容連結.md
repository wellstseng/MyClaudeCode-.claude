## 知識

- [臨] 專案根目錄搬家或改名後，記憶系統這邊要改：`memory/project-registry.json` 的 root 與 slug（slug＝小寫路徑、非英數轉 `-`、底線保留）；改完 POST 向量服務 `/index/incremental`，分層名跟著路徑重建，用 `/status` 的 layers 確認。不改的話舊條目指向不存在的路徑，該專案的向量檢索會整層消失且無告警。
- [臨] Claude Code 這邊要改：`~/.claude/projects/` 下按路徑命名的對話資料夾（不改則 `--resume` 舊 sessionId 找不到）、`~/.claude.json` 的 `projects` 鍵（信任與工具設定）。資料夾名以 `-` 開頭，shell 要寫 `mv -- ./-名字`。
- [臨] 環境這邊要改：指進專案的符號連結、crontab、launchd、常駐程序管理器記的啟動路徑（要刪掉後從新路徑重新啟動再存檔，光重啟會沿用舊路徑）。
- [臨] 舊路徑留一個符號連結指到新位置：Python 虛擬環境與 conda 環境把絕對路徑寫死在上百個檔裡，重建不值得；改名（不只搬位置）的資料夾連結救不到，要實際改寫。
- [臨] 批次改寫路徑字串要涵蓋三種寫法：絕對路徑與 `~`、`$HOME`、程式裡的分段寫法（`Path.home() / "a" / "b"`、`join(homedir(), "a", "b")`）；只掃字面路徑會漏掉分段寫法。
- [臨] 會 `git add -A` 的自動同步排程啟用前，先查新搬進來的資料（照片、模型、資料庫）有沒有被 .gitignore 排除。
