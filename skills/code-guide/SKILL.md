# Skill：code-guide

> 全域 skill，零專案耦合 — 知識庫位置、版控種類等環境差異於執行當下偵測。開發者接手不熟的系統前，由 AI 先讀原始碼產出「導讀地圖」——先給地圖再進隧道，精讀時間花在真正值得精讀的 20%。產出 = 8 區塊固定結構（模板 [assets/template-guide.md](assets/template-guide.md)，寫法要領 [references/methodology.md](references/methodology.md)）。

## 觸發與目標解析

`/code-guide <目標>`，目標三型態：

| 型態 | 判定 | 定位方式 |
|------|------|---------|
| 檔案路徑 | 含 `/`、`\` 或副檔名 | 直接 Read |
| 類別名 | 單一識別字（PascalCase） | Glob `**/<名>.*` → 沒中再 Grep `class <名>` |
| 系統名 | 自然語言 / 多詞描述（如「戰鬥技能系統」） | 查知識庫 + Grep 關鍵字 → 列檔案清單請使用者確認範圍 |

## 核心鐵則

1. **行號必須是執行當下 Read/Grep 取得** — 禁止憑記憶或舊文件寫行號
2. **所有程式碼引用一律 `[檔名:行號](相對路徑#L行號)`** 可點擊連結，相對路徑以專案根為基準
3. **全程繁體中文**，技術術語可英文；**表格只放短事實**，因果解釋寫在表格外的敘述
4. **讀者是資深開發者**：跳過語言基礎，直入結構與設計決策
5. **知識庫與原始碼矛盾 → 以原始碼為準**，過時文件點名寫進區塊 8

## 工作流程

### Step 0：前置知識查詢
- 偵測專案知識庫並查與目標相關的條目：常見位置 `_AIDocs/_INDEX.md`、`.claude/memory/MEMORY.md`、專案 `CLAUDE.md` 指到的其他索引；**都沒有就跳過本步**
- 已有知識直接引用並標來源；時效存疑的標成「需驗證」，Step 2 與原始碼對質
- 完成判定：列出「可引用」「需驗證」兩份清單（可為空）

### Step 1：定位與規模分級
- 依目標型態定位檔案（見上表）
- 系統名 / 跨檔 → 先列涉及檔案清單（路徑 + 行數 + 一句話角色），AskUserQuestion 確認範圍才開讀
- 規模分級：
  - 單檔 → 直接全讀
  - 跨檔 ≤ 8 檔且總行數 ≤ 5000 → 全讀，產一張系統級地圖
  - 超過 → 本次只產「入口 + 資料流」總圖，其餘子系統建議拆多次 `/code-guide`
  - 整個專案 → 不適用單次跑；引導使用者由架構文件選子系統逐一導讀
- 完成判定：檔案清單已確定（跨檔需使用者確認，單檔免）

### Step 2：讀碼
- 跨檔先讀入口與資料流，再讀實作
- 邊讀邊蒐集 8 區塊素材：核心欄位、對外動詞、各入口的觸發來源與參數、不變量、stale 容忍分界
- Step 0 的「需驗證」知識在此對質，矛盾記入區塊 8 素材
- 完成判定：8 區塊素材齊備 — 哪區缺就回頭補讀，**不准腦補**

### Step 3：填模板產出
- Read `assets/template-guide.md` → 按 8 區塊填入，**禁止改章節順序與標題**
- 某區寫法拿不準時 Read `references/methodology.md` 對應小節
- 產出先寫到系統暫存目錄（Windows：`$env:TEMP\code-guide-draft.md`），**不污染專案工作副本**

### Step 4：錨點硬驗證
```
python scripts/check-anchors.py <草稿路徑> --root <專案根絕對路徑>
```
- exit 0 → Step 5；exit ≠ 0 → 依輸出違規清單修正錨點後重跑
- **禁止跳過此步驟自行判斷「行號應該沒錯」**

### Step 5：輸出去向
- **預設**：驗證過的內容直接輸出在對話，不落專案檔
- **使用者明說要存檔**才寫入專案知識庫（慣例 `_AIDocs/CodeGuide_<目標>.md`；專案無知識庫慣例則先問位置），開頭必含版本標頭：

  > 對應版本：`<版控版號>`（SVN rev / git short hash，執行當下取得）/ `<日期>`。程式碼變更後本導讀需重新產生。

  並依該專案慣例同步知識庫索引 / changelog
- 完成判定：使用者拿到導讀地圖 + 一句話告知錨點已通過驗證

## 必備檔案

| 檔 | 用途 |
|----|------|
| assets/template-guide.md | 8 區塊導讀地圖模板（結構骨架 + 各區填寫指引） |
| references/methodology.md | 各區塊寫法要領與設計原理（拿不準時按需讀） |
| scripts/check-anchors.py | 錨點驗證器：路徑存在 + 行號 ≤ 檔案總行數 |

## 反模式

- ❌ 憑記憶 / 舊文件寫行號（Step 4 必擋，別賭）
- ❌ 跨檔系統不確認範圍就開讀（token 黑洞）
- ❌ 逐行講解演算法（講不變量，不講實作流水帳）
- ❌ 把導讀寫成 API 文件（導讀是一次性鷹架，不是長期維護文件）
- ❌ 未經使用者明說就寫檔進專案
