## 知識

- [臨] Wells 要求：程式檢查/審查的回報必須「分類」呈現（如：問題、風險、一致性、小缺陷），並「簡單扼要」整理說明改動內容，不要流水帳。
- [臨] 適用場景：任何 code review、改動檢查、遷移驗證的最終回報。先分類、每類條列、每條一句話講清楚結論與位置。
